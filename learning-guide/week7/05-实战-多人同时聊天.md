## 5.1 点火之前：快测再过一遍

正式上真实模型之前，先确认你的引擎在小模型上行为正确：

```bash
.venv/bin/pytest tests/test_w7.py -m "not slow"
```

四个快测用的都是老熟人 `mini_model`（64 词表、2 层的 MiniTransformer，
`torch.manual_seed(0)` 固定权重）配一个**玩具分词器** `ToyTokenizer`
（在 `tests/conftest.py` 里）。这个分词器值得看一眼——它是引擎测试的关键道具：

```python
class ToyTokenizer:
    """一个玩具分词器：按空格切词，词表是从训练语料里现建的。

    只实现引擎需要的两个方法：encode / decode。
    """

    def __init__(self, corpus):
        vocab = sorted({w for text in corpus for w in text.split()})
        self.stoi = {w: i for i, w in enumerate(vocab)}
        self.itos = {i: w for w, i in self.stoi.items()}
        self.eos_token_id = None
    ...
```

它的全部本事就是：按空格切词、`encode` 查表、`decode` 反查（词表外的 id
用 `<id>` 占位兜住）。但请注意——**它恰好满足引擎对分词器的全部要求**：
`encode` / `decode` 两个方法。这就是"鸭子类型"的好处：引擎不关心分词器
是玩具还是 HuggingFace 的大家伙，会这两招就能上岗。四个快测的合同
（对拍、批量一致性、流式拼接、停止符）第 3 章已经逐个讲过，不再重复。

## 5.2 实战一：四个用户一起问

快测全绿后，点火真实模型。新建一个脚本（比如 `play_w7_chat.py`）：

```python
import time

from minivllm.engine.llm import LLM
from minivllm.sampling.sampler import SamplingParams

llm = LLM(model_name="Qwen/Qwen3-0.6B", max_model_len=512, max_num_seqs=4)

prompts = [
    "The capital of France is",
    "1+1=",
    "用一句话解释什么是递归：",
    "Write a haiku about the ocean:",
]
params = SamplingParams(temperature=0.0, max_new_tokens=24)  # 贪心，结果可复现

t0 = time.time()
outs = llm.generate(prompts, params)
print(f"4 个请求一起跑完，耗时 {time.time() - t0:.1f}s")
for p, o in zip(prompts, outs):
    print(f"[rid={o.request_id} finish={o.finish_reason}] {p!r}")
    print(f"  -> {o.text!r}")
```

两个参数说明：`max_model_len=512` 和 `max_num_seqs=4` 纯属"给本机省内存"
——按第 4 章的默认算法，KV cache 只需装下 4 × 512 = 2048 个槽位，
比默认值小得多，加载快、跑起来也轻快。

笔者机器（Mac，MPS）上的实测输出：

```
4 个请求一起跑完，耗时 2.3s
[rid=0 finish=length] 'The capital of France is'
  -> ' Paris. The capital of Italy is Rome. The capital of Spain is Madrid. ...'
[rid=1 finish=length] '1+1='
  -> '2, 1+1=2, 1+1=2, 1+1=2, '
[rid=2 finish=length] '用一句话解释什么是递归：'
  -> '递归是一种编程方法，它通过调用自身函数来实现计算。...'
[rid=3 finish=length] 'Write a haiku about the ocean:'
  -> ' the ocean is a place where the sun and moon shine, and the waves are like a mirror. ...'
```

停下来品味一下这几行输出背后的分量：

- **四个请求是一起跑的**。rid=2 的中文请求提示词更长，rid=1 的算术题更短——
  它们 prefill 先后上车、decode 齐头并进，全程 continuous batching
  （Week 5 的调度器在干活）；
- **全部 `finish=length`**：我们设了 `max_new_tokens=24`，大家都生成满 24 个词
  才下车。贪心采样（`temperature=0.0`）下结果完全确定，你重跑多少遍都一字不差；
- rid=1 的 `'2, 1+1=2, ...'` 看起来有点复读机——0.6B 的小模型 + 贪心采样
  就是这水平，**引擎是对的，模型就这点本事**。想让它话多一点，把
  `temperature` 调到 0.7 试试（那是 Week 6 采样器的舞台）。

## 5.3 实战二：打字机效果

再体验 `stream`。同一个脚本后面接上：

```python
t0 = time.time()
first = None
pieces = []
for piece in llm.stream("The capital of France is", SamplingParams(max_new_tokens=16)):
    if first is None:
        first = time.time() - t0
    pieces.append(piece)
    print(repr(piece))          # 看每一片长什么样
print(f"首片延迟 {first * 1000:.0f} ms，共 {len(pieces)} 片")
print("拼起来:", repr("".join(pieces)))
```

实测输出：

```
' Paris'
'.'
' The'
' capital'
' of'
' Italy'
...
首片延迟 54 ms，共 16 片
拼起来: ' Paris. The capital of Italy is Rome. The capital of Spain is Madrid.'
```

两个观察正好印证第 3 章的算法：

1. **片的边界是"词和标点"，不是 token 的生硬切法**。`' Paris'` 是一个片，
  `'.'` 自己占一个片——这正是"全文 decode 再减前缀"的效果：每一片都是
  **能正确显示的文字**，永远不会有半个字的乱码；
2. **首片延迟只有几十毫秒**。从调用 `stream` 到拿到 `' Paris'` 这第一片，
  包含了 prefill 整段提示词 + 采出第一个词 + decode 文本——总共 54 ms
  （课程在 `figures/data/bench.json` 里记录的 TTFT 实测是 62 ms，同量级）。
  这就是流式的意义：**用户不用等全部 16 个词，几十毫秒后就开始有东西看**。
  把 `max_new_tokens` 开到 200 再对比"等 `generate` 全跑完"的体感，
  差距会更明显。

## 5.4 终审：slow 测试

最后是本周的期末考试——真实模型端到端：

```bash
.venv/bin/pytest tests/test_w7.py -m slow
```

只有一个用例 `test_llm_facade_real_model`，但它把你本周写的**所有东西**
串起来考了一遍：

```python
llm = llm_mod.LLM(
    model_name="Qwen/Qwen3-0.6B", max_model_len=512, max_num_seqs=4
)
outs = llm.generate(
    ["The capital of France is", "1+1="],
    SamplingParams(max_new_tokens=16),
)
assert "Paris" in outs[0].text
assert "2" in outs[1].text

pieces = list(llm.stream("The capital of France is", SamplingParams(max_new_tokens=16)))
assert "Paris" in "".join(pieces)
```

注意它检查的**不是**某个 token id，而是**语义层面**的结果：法国首都的答案里
要有 "Paris"，1+1 的答案里要有 "2"。这条断言链从你写的 `LLM.generate`
一路向下：`_tokenize` → `engine.generate` → `add_request` → 无数字符
`step`（点名、prefill、decode、采样、登记）→ `_make_output` →
`tokenizer.decode`——任何一环错了，"Paris" 都不会出现。

> ⚠️ **易踩坑：** slow 测试要加载 1.4 GB 权重，第一次跑耐心等一两分钟；
> 机器没联网的话加 `HF_HUB_OFFLINE=1` 走本地缓存（Week 1 环境搭建时已经下好）。
> 如果报权重相关的错，先确认 Week 6 的 `from_pretrained` 那几条链路是绿的
> （`pytest tests/test_w6_qwen3.py -m slow`）。

> 📌 **对标 vLLM：** 你刚做的事，等价于真实 vLLM 文档里的第一段示例代码：
> `LLM(model=...)` + `llm.generate(prompts, sampling_params)`。连参数名
> （`max_model_len`、`max_num_seqs`）都是照着起的。Week 8 我们会用同一批
> prompt 让 minivllm 和真实 vLLM 同场赛跑。

> 📌 **划重点：** 快测保正确（对拍、顺序、流式、停止符），slow 测试保
> "真实模型上真的能说人话"。两层都绿，你的引擎才算正式出厂。
